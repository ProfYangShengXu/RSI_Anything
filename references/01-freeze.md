# 01 冻结（G1）

## 预注册四项：少一项后面全是白跑

```
H0        起点：改之前的版本 + 它的读数（要能复现）
预算      硬上限（max_calls / max_wall_s / max_usd）+ 记账口径（in/out token、缓存、外部 API）
判据      谁算成功；必须能被机器判；分母写清楚（全部题 / 有产物的题）
样本量    先按要分辨的差距算需要多少题，再决定跑多少
聚合口径  失败算 0 / 剔除 / 单列；GT 质量差的题预先剔除还是保留
```

## 判据体检（四件套）—— 只做“造一个假答案”是不够的

单一样本只能测一个方向。判据的漏洞至少有三类（取巧、部分分、对真改进迟钝），
所以体检要同时给出 **标定 / 对抗集 / 敏感度 / 鲁棒性** 四组读数。

### A 标定（三档，必须带阈值）

```
s_orig   原版产物        （当前系统的真实水平）
s_ref    参考解          ★ 必须 = max
s_junk   垃圾（空文件 / 随机文本）  ★ 必须 ≤ 0.1 × s_ref
```

**区分度门槛**：`s_ref - s_orig ≥ 0.1`。
达不到就说明这道题本身没区分度（原版已经快满分），换题，不要加判据。

### B 对抗集（≥ 5 类，逐类报分）

```
① 空产出            建了文件但没内容
② 抄题面            把指令原文/题目描述当产物交上去
③ 只满足关键词      presence / 长度 / 命中某个词，其余胡写
④ 结构对内容错      schema 全对，数值/引用/顺序错（最像真的）
⑤ 超集蒙对          正确内容埋在大量无关内容里
```

**记 `s_fake_max` = 五类里的最高分**。两条硬门槛：

```
每一类都必须单独报分（不许只报最差那个，不许剔除）
s_ref - s_fake_max ≥ 0.5 × (s_ref - s_orig)
```

第二条的意思：**判据识别假答案的力度，至少得达到它识别真改进力度的一半。**
两边都用 `ref - orig` 做基准，所以不依赖绝对分数。

### C 敏感度（正对照）

拿一个**已知有效**的改动（哪怕手工造），判据必须至少涨到：

```
Δ_judge ≥ 0.5 × (s_ref - s_orig)
```

否则判据对真改进太迟钝：它能判真假，但判不出好坏 —— 后面 G4 拿它测收益，测不出来。

### D 鲁棒性

```
同一份产物判 3 次，分差 ≤ 0.02
换题序 / 换批量（单独跑 vs 混跑）分差 ≤ 0.02
判据文件 hash 冻结（跑前跑后不能变）
```

### 不过怎么办

```
任一类假答案超过上限      → 判据不合格，停。先修判据，不要跑模型
区分度 < 0.1              → 题目没区分度，换题
敏感度不达标              → 判据只能判真假不能判好坏，补一个能反映改进的面
```

★ 另外一条（来自 SpecBench）：**判据只能读一个面时会招来作弊**（例如只看测试是否通过）。
若判据实际只读一个面，必须在 prereg 里写明，并补一个独立面做交叉；不能就说明为什么不能。

## 题面体检三检（和判据体检是两件事）

```
① 唯一吗   标准答案是否唯一？描述够不够解题？
② 可达吗   题目要求的东西在环境里真的存在吗（文件/帧/字段/接口）
③ 谁体检   做体检的人不能是写判据的人
```

## 冻结 hash

```bash
python scripts/freeze_hashes.py runs/<id> --code <repo> --judge <judge.py> --data <tasks/>
```

跑前跑后各算一次，变了就作废。

## 预算的两个常见坑

```
① 上限只写在命令行，执行体自己不看 → 跑到天荒地老
② 一臂提前结束、一臂跑满 → 你比的是“多试几次”，不是方法
```
