# 03 归因与解法（G3）

## 三个出口（每条失败必须落到一个）

```
壳的缺陷           能改，改得起
模型能力/预算不足   改壳没用，换模型或加预算
不可归因           证据不够，认了，不改
```

## 粒度三字段（写不出 component 就是还没定位）

```
component   提示词 / 工具 / 记忆 / 编排 / 技能 / 判据 / 数据管线
locator     字段名或函数行号
granularity fine（单字段/单行）/ coarse（整段）
```

`coarse` 允许，但必须同时给撤销边界（整段换回原版）。

## 多因并存

一条失败常有两个以上原因。**归因输出是列表**，每条带证据指针与置信档；
**改动只挑一条主因**（影响面 × 可改性），其余登记为“已知未处理”。
分不清主次 → 先做一条能分离它们的探针，别一次改两处。

## 解法来源三档

```
A 档  现成先验   必须：出处 + 适用条件 + 至少一条反例。缺一降级到 C
B 档  项目经验库  必须挂实验记录 ID
C 档  现场推断   只能当假设，配一条能证伪的探针，验完才允许改
```

## 强制探针

**每个候选都要有“改前执行 vs 改后执行”的行为对比。**
来源分档只决定“先信谁”，不豁免验证。

## 撤销三件套

```
① 改前快照（原文件副本 + sha256）
② 可执行的撤销动作（不是“手动改回去”）
③ 撤销后自检：哪条判据必须重新变绿
```

## 改动单（CU）必须回答

```
归因是哪一条（引用 finding id）
改哪个组件的哪一行
为什么信这个解法（来源档 + 证据）
探针怎么跑、看什么
怎么撤、撤完怎么验
预期变什么、预期不变什么
```
